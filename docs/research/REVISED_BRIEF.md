# Revised Phase 2 execution brief

Improve the existing Swift package, preserving source compatibility and repository isolation. Audit concrete defects before changing code. Treat provider permission, relevance, availability, latency and resource consumption as separate gates.

1. Review current official service contracts and representative implementation/issue/community sources. Rank at least ten plausible candidates. Implement only documented, independently permitted interfaces; keep evaluation access distinct from commercial production authorization.
2. Establish a versioned public corpus of at least fifty queries with intent/freshness/locale criteria. Execute a quota-bounded declared subset. Record per-result grades and failures; never convert the old query-level grades into missing Precision@5 or nDCG data.
3. Reduce client overhead with retained ephemeral URLSession connections and bounded chunk reading. Preserve HTTPS-only endpoints, redirect rejection, no cookies/credentials/cache and prompt individual-task cancellation.
4. Define concurrency semantics: bounded active searches, bounded per-provider admission, FIFO cancellation-aware waits, queue-inclusive overall deadlines and a bounded pending count. Share only identical in-flight requests within one end-user client; one subscriber cancelling must not cancel the others. Cancel upstream when the last subscriber leaves.
5. Add an explicit bounded first-success strategy and per-provider budgets. Cancel and record losing attempts. Measure wall latency, request count and relevance separately. Do not assume racing improves ranking or that cancellation refunds quota. Keep conservative sequential defaults.
6. Compare the reference revision and new revision using the same native consumer harness, public inputs, result limit and network, alternating order where possible. Report small-sample limitations and upstream caching. Include a controlled identical-request burst to measure successful consumers per actual HTTP request.
7. Add explicit country/time parameters where documented; do not silently drop unsupported options or rewrite queries. Defer fusion, domain reshuffling, persistent caches and extra dependencies unless evidence demonstrates a worthwhile benefit.
8. Run deterministic tests, strict concurrency, release/Apple SDK builds, independent consumers, bounded native live requests, privacy/license review and secret scanning. Physical device and multiple-network work must be labeled pending when unavailable.
9. Publish code, reproducible methodology, sanitized observations, grading logic, results and limitations to the existing repository. Do not publish third-party content or restricted provider comparisons. Do not create a stable release while technical or usage-rights gates remain open.
