# Commercial-use audit — V3, 2026-11-02

**No bundled general-web provider is commercially cleared for the required free, anonymous, direct-device deployment.** This is an evidence classification for that exact deployment, not a claim that all commercial use of these companies' products is forbidden. Written permissions were neither assumed nor requested on the user's behalf.

MIT covers LapisWebSearch's original Swift code. No third-party search implementation or dataset was incorporated. Server software licenses below do not license endpoint traffic, trademarks or result content. Third-party webpages retain their own rights; receiving a URL/snippet does not license arbitrary reproduction, training or resale.

## Classification

- **Commercially cleared:** explicit official permission for the intended automated commercial integration, or written authorization.
- **Conditionally permitted:** explicit commercial permission with specific satisfiable conditions; conditions must be checked for the actual deployment.
- **Unverified:** insufficient evidence for the required authorization; absence of a prohibition is not clearance.
- **Restricted:** a known condition conflicts with this deployment without additional permission/payment/credentials.
- **Technically unavailable:** inability to use the endpoint reliably, independently of rights. No untested engine was assigned this status merely because it was excluded.

A provider can have a restricted commercial status and still work technically. All rows were reviewed on **2026-11-02**. No candidate below establishes unlimited access.

## Commercial selection in code

`LapisWebSearch()` now selects **no provider**, returning `noEligibleProviders` before any networking. This is an intentional pre-stable behavioral change from V2; ordinary Swift call syntax still compiles. Explicit adapters remain usable for authorized experiments. The CLI likewise requires `--provider`.

`SearchConfiguration(providerPolicy: .requireCommercialClearance)` validates the **whole configured set before scheduling**, so an unverified fallback cannot accidentally receive a query. It accepts only `commerciallyCleared` declarations with HTTPS evidence; conditional status is insufficient. All bundled adapters fail this policy. It does not silently choose a paid service or filter away rejected adapters.

`ProviderUsage` is a provider author's assessment, not automated legal verification. Custom code can make false declarations; the application must review its evidence. An application with written deployment authorization can implement a thin forwarding SearchProvider declaring its scoped assessment, with the authorization reference. That does not require duplicating the adapter or falsifying the package's general anonymous-access status. Do not put confidential authorization text or credentials in a public package.

## Questions prepared for providers — not sent

1. Do your current terms expressly permit a commercially distributed iOS/iPadOS/macOS app to call the documented anonymous endpoint directly, with no developer/user accounts, keys or payment? Does each end user need an agreement?
2. May the app display normalized titles, URLs and short snippets, feed them to a local model at inference time, deduplicate and use bounded fallback? Specify attribution, retention, transient caching and redistribution obligations; training is not requested.
3. What sustained/burst/daily/monthly quotas apply per device, public IP and application, including NAT/carrier networks? How are Retry-After and quota resets signalled? Can this remain free at the expected deployment volume?
4. May we publish sanitized latency and graded retrieval measurements? What geography, age, privacy, subprocessors and retention conditions apply?
