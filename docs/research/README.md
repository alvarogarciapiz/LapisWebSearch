# LAPIS Research: native web discovery on small devices

LapisWebSearch is a transparent engineering research preview. It is not peer-reviewed work, a service authorization or a production certification. The question is whether a small native Swift client can obtain useful general-web results without an application backend, keys, accounts, paid mandatory APIs, browser automation or AI inference dependencies.

Lapis already owns extraction, retrieval, context budgeting and citations. A real native DuckDuckGo blocking failure motivated the independent discovery package. That background did not justify evasion or treating diagnostic HTTP success as application reliability.

Start with [V3 results](RESULTS.md), the [commercial-use audit](COMMERCIAL_USE_AUDIT.md), [provider landscape](SEARCH_PROVIDER_LANDSCAPE.md) and [pinned source inspection](GITHUB_SOURCE_AUDIT.md). [Methodology](METHODOLOGY.md), [benchmark commands/labels](BENCHMARKS.md) and [limitations](LIMITATIONS.md) qualify every measurement. The [V3 article](LAPIS_RESEARCH_ARTICLE.md) is a draft for later editorial review/publication.

V2 [audit](AUDIT.md), [revised prompt](REVISED_BRIEF.md), [results](RESULTS_V2.md), [landscape](SEARCH_PROVIDER_LANDSCAPE_V2.md), [methods](METHODOLOGY_V2.md), [benchmarks](BENCHMARKS_V2.md), [limitations](LIMITATIONS_V2.md) and [article draft](ARTICLE.md) remain historical evidence. Phase-1 data is in [VALIDATION.md](../VALIDATION.md). Never combine their sample sizes/rubrics into an invented reliability percentage.

Evidence categories remain distinct: genuine native responses, standalone probes, deterministic/injected failures, external provider claims, engineering decisions and unverified assumptions. Original public input is in `benchmarks/v1/`; V3 labels/metrics/execution are in `benchmarks/v3/`. No private application search histories or raw third-party outputs are published. Default diagnostic exports omit queries, result content and protocol IDs.
